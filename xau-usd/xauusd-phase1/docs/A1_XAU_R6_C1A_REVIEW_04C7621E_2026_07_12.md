The accepted opportunity has already passed:

```text

```

but the schema still permits:

```json

  "minimum": 0,
  "maximum": 6

```

This directly misses the prior audit's requested `4..6` accepted-row bound.

**Required correction:**

```json
"impulse_bullish_bars": {
  "minimum": 4,
  "maximum": 6,
  "type": "integer"
}
```

### 3.2 Two outcome-blind row metrics remain undefined

The prior audit froze:

```text
breakdown_distance_atr =
  (box_low - breakdown_close) / A_break

reclaim_touch_distance_atr =
  (reclaim_high - box_low) / A_reclaim
```

The amended schema constrains their ranges, but neither the preregistration nor rule lock defines these formulas. Different sign conventions would produce different accepted rows while still satisfying the field names.

Add a locked `derived_metrics` object and the same formulas in the preregistration. To remove all parity discretion, include:

```json
"derived_metrics": {
  "impulse_range_atr": "(impulse_high-impulse_low)/A_impulse",
  "impulse_net_advance_atr": "(h4_close_shift_8-h4_open_shift_13)/A_impulse",
  "impulse_final_location": "(h4_close_shift_8-impulse_low)/(impulse_high-impulse_low)",
  "box_width_atr": "(box_high-box_low)/A_box",
  "box_net_drift_atr": "abs(h4_close_shift_2-h4_open_shift_7)/A_box",
  "breakdown_distance_atr": "(box_low-h4_close_shift_1)/A_break",
  "breakdown_body_fraction": "abs(h4_close_shift_1-h4_open_shift_1)/(h4_high_shift_1-h4_low_shift_1)",
  "breakdown_close_location": "(h4_close_shift_1-h4_low_shift_1)/(h4_high_shift_1-h4_low_shift_1)",
  "reclaim_touch_distance_atr": "(reclaim_h1_high-box_low)/A_reclaim",
  "reclaim_body_fraction": "abs(reclaim_h1_close-reclaim_h1_open)/(reclaim_h1_high-reclaim_h1_low)",
  "reclaim_close_location": "(reclaim_h1_close-reclaim_h1_low)/(reclaim_h1_high-reclaim_h1_low)"
}
```

Zero/nonpositive denominators must terminate as `DATA_UNAVAILABLE`.

### 3.3 Machine-readable half boundaries conflict with the amended half-open contract

The preregistration correctly freezes:

```text
early = [2016-07-01, 2021-07-01)
late  = [2021-07-01, 2026-07-01)
```

but the rule lock still contains date pairs ending in `2021-06-30` and `2026-06-30`. Those can be interpreted as inclusive calendar dates, while the amended contract uses exact half-open timestamps.

Replace with:

```json
"halves": {
  "early": {
    "from_inclusive": "2016-07-01T00:00:00",
    "to_exclusive": "2021-07-01T00:00:00"
  },
  "late": {
    "from_inclusive": "2021-07-01T00:00:00",
    "to_exclusive": "2026-07-01T00:00:00"
  }
}
```

### 3.4 The entry expiry key retains the superseded “scheduled close” wording

The amended semantics correctly define:

```text
decision_time = next native H1 bar open
entry tick <= decision_time + 15 minutes
```

but the JSON key remains:

```text
expiry_minutes_after_scheduled_h1_close
```

That wording can reintroduce nominal `open + 1 hour` behavior across session gaps.

Replace it with:

```json
"expiry_minutes_after_decision_time": 15
```

and remove the old key.

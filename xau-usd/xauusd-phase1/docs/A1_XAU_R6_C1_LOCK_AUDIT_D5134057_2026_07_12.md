# 2. Blocking ambiguities and defects

## 2.1 Router V1 is named but not pinned

The lock says only `ROUTER_V1`. It does not pin:

- source commit/path/blob;
- input values;
- state-priority order;
- EMA/ATR/percentile/median semantics;
- unavailable-data behavior.

This is material. A Python implementation could call a different “Router V1” and still appear contract-compliant.

The canonical source currently is:

```text
path:
  xau-usd/xauusd-phase1/mt5/Experts/A1XauM5MomentumContinuationExecutor.mq5

source commit:
  d51340574d90a39fe0032e54e4a8252370c19058

Git blob:
  d59338facaa01032a47c71186e64e1ba9f1dba8f
```

C1A must pin that identity and the exact Router V1 inputs.

## 2.2 Timestamp and scheduled-close basis is undefined

The schema uses JSON Schema `date-time`, but the source data is native MT5 broker-server wall-clock data without a frozen historical UTC-offset mapping.

Undefined choices include:

- UTC versus server time;
- whether H1/H4 close equals open + 1h/4h;
- weekend/session gaps;
- which H1 bars are “subsequently completed”;
- whether a tick sharing the boundary second belongs to the old or new bar;
- the meaning and scope of `entry_tick_sequence`;
- whether half/year/month assignment uses breakdown, reclaim, decision, or entry time.

These choices can change the opportunity count and bucket gates.

## 2.3 `point` and `digits` are missing from the contract/schema

The row requires:

```text
spread_points
stop_points
```

but the contract snapshot and schema contain `tick_size` only, not `SYMBOL_POINT` or symbol digits.

Current Capital.com happens to expose point and tick size compatibly, but parity must not rely on that unstated assumption.

## 2.4 Contract-risk price is ambiguous

The rule contains both:

```text
structural stop normalized upward to one tick
```

and:

```text
OrderCalcProfit at normalized structural stop plus one tick
```

The schema does not state whether `stop_points` ends at the structural stop or at the extra-tick conservative risk price.

It also does not freeze initial-stop validity relative to ask, stops level, and freeze level.

## 2.5 Candidate and episode IDs are required but undefined

`candidate_id` and `episode_id` are mandatory schema fields, but only `box_id` has a canonical construction. Reproducible identity needs canonical field order, timestamps, price formatting, direction, and delimiter rules.

## 2.6 Excluded-candidate accounting is internally ambiguous

The schema requires entry tick, price, stop, and contract-risk fields for every row, while also requiring `availability_status` and `exclusion_reason`.

Candidates rejected before entry availability cannot satisfy the schema. C1 does not state whether:

- excluded candidates are rows;
- only raw opportunities are rows;
- exclusions are aggregate funnel counters;
- each H4 decision anchor receives exactly one terminal classification.

This must be resolved before implementation.

## 2.7 Bucket and contiguous-window mechanics are not canonical

The numeric gates are correct, but the lock does not state:

- timestamp used for assignment;
- inclusive/exclusive half boundaries;
- zero-filled months;
- exact July–June labeling;
- whether contiguous 24 months means calendar months or elapsed days;
- how many windows exist.

These can change the 25% and 40% concentration decisions.

## 3.6 Freeze suppression release ordering

Suppression starts immediately after a valid breakdown.

At each later H4 completion:

1. process release using that just-completed bar;
2. release if its close is at or above original box mid;
3. otherwise release when the 12th additional H4 bar completes;
4. then evaluate that same completed H4 bar as a possible new shift-1 candidate.

Thus the release bar may seed a new candidate. Signal resolution does not release suppression early. Position or P/L state is never consulted.

# 3. Why Python is being used

The purpose is not to create an autonomous trader.

The purpose is to test this falsifiable claim:

> Given a raw breakout-retest signal generated by the existing deterministic logic, a small, calibrated, reproducible Python model can rank the signal’s future quality better than both the raw EA and simple deterministic filters, while preserving useful frequency.

The model must beat:

```text
raw breakout-retest
loose counter-trend veto
H1 alignment
light retest confirmation
```

If it does not add material, statistically supported value, retire ML and keep the simpler deterministic rule.

# 11. Fuzzy setup grouping

Exact hashes are not sufficient.

Create:

```text
setup_group_id
```

Primary fuzzy grouping rule:

Signals are in the same setup group when all are true:

```text
symbol is equal
base family is equal
direction is equal
absolute level-price difference <= 0.10 × earlier-signal M5 ATR14
decision timestamps differ by <= 10 minutes
break/retest event windows overlap
overall connected-component span <= 20 minutes
```

Implementation:

1. exact-deduplicate first;
2. sort by time;
3. build graph edges from the primary fuzzy rule;
4. find connected components;
5. split components whose total span exceeds 20 minutes;
6. select earliest valid decision as canonical model row;
7. aggregate lane names, magics, duplicate count, and source row IDs;
8. assign one `setup_group_id`.

Rules:

```text
one setup group cannot cross train/test boundaries
duplicate count is metadata, not a feature
lane identity is metadata, not a feature
```

Generate sensitivity diagnostics at:

```text
0.05 ATR
0.10 ATR primary
0.20 ATR
```

Only `0.10 ATR` is used for the locked dataset.

# 13. Label and virtual-execution contract

The label contract must be hash-locked before dataset construction.

## 13.1 Entry

```text
decision uses completed bars only
LONG fills at first fresh ask after decision
SHORT fills at first fresh bid after decision
no historical same-bar fill
entry expires at the close of the next M5 bar
```

If no eligible fresh tick arrives:

```text
CANCELLED_NO_FRESH_TICK
```

Cancelled signals remain in the signal audit but do not become supervised outcome rows.

## 13.2 Risk geometry

```text
risk_price = max(
    raw signal risk,
    broker stops level + 5 points,
    3 × spread at virtual fill,
    300 XAU points
)

TP distance = 1.50 × risk_price
```

## 13.3 Quote side

```text
LONG:
  entry = ask
  SL/TP/timeout exit = bid

SHORT:
  entry = bid
  SL/TP/timeout exit = ask
```

## 13.4 Holding horizon

Lock:

```text
MAX_HOLD_ACTIVE_M5_BARS = 288
```

This equals 24 active-market hours.

Definition:

```text
count only completed M5 bars with market data
weekend/market closure does not consume the active-bar timeout
position remains exposed across closure
first quote after reopen may produce gap SL/TP
```

Timeout:

```text
after the 288th active M5 bar closes,
exit at the first fresh executable quote
```

If no fresh quote occurs within 15 active minutes:

```text
DATA_UNRESOLVED_TIMEOUT
```

## 13.5 Gap handling

If the first executable quote crosses SL or TP:

```text
exit at the actual quote
record slippage relative to requested level
```

Do not force a fill at the requested level.

## 13.6 Ambiguous aggregated data

True tick data is required for candidate labels.

If only aggregated data is available and both SL/TP ordering is ambiguous:

```text
label_status = EXECUTION_AMBIGUITY
exclude from supervised candidate training
retain in audit
```

Do not resolve promotion labels from OHLC adverse-first assumptions.

# 19. Ordered V1 feature registry

All model features are numeric.

Categorical lane, magic, level-name, day-of-week, and session bucket are logged but excluded from V1 models.

Direction is incorporated by direction-normalizing signed features.

Let:

```text
direction_sign = +1 LONG
direction_sign = -1 SHORT
```

Ordered list:

```text
1. h1_ema20_slope_aligned_atr
   = direction_sign × (EMA20_H1[1] - EMA20_H1[4]) / ATR14_H1[1]

2. retest_penetration_atr

3. confirmation_body_ratio

4. cost_R

5. confirmation_close_location_aligned
   LONG = (close-low)/(high-low)
   SHORT = 1 - (close-low)/(high-low)

6. break_distance_atr

7. m15_ema20_slope_aligned_atr

8. bars_break_to_retest_scaled
   = min(bars, 20) / 20

9. impulse_alignment_12
   = direction_sign × ret12_m5_atr

10. price_h1_ema20_distance_aligned_atr
    = direction_sign × (price - EMA20_H1[1]) / ATR14_H1[1]

11. m5_atr_percentile_trailing_20d

12. spread_percentile_session_trailing_20d

13. d1_trend_score_aligned
    = direction_sign × (EMA20_D1[1] - EMA20_D1[6]) / ATR14_D1[1]

14. range_compression_ratio_20

15. tick_volume_ratio_20

16. minutes_from_session_start_scaled
```


# 21. Deterministic regime classifier

Regime coverage must be objective.

Use completed D1 bars.

```text
d1_trend_score =
    (EMA20_D1[1] - EMA20_D1[6]) / ATR14_D1[1]
```

Classification:

```text
RISING:
  D1 close[1] > EMA20_D1[1]
  AND d1_trend_score >= +0.25

FALLING:
  D1 close[1] < EMA20_D1[1]
  AND d1_trend_score <= -0.25

MIXED:
  all other valid states

UNKNOWN:
  required data unavailable
```

`UNKNOWN` does not count toward regime coverage.

The regime classifier is:

```text
reporting / coverage only
not an automatic model feature unless feature budget reaches item 13
```

# 23. Data splitting

Never use:

```text
train_test_split(shuffle=True)
KFold(shuffle=True)
StratifiedKFold with random ordering
random row sampling
```

Use purged expanding walk-forward validation.

Every sample has:

```text
event_start = decision_time_utc
event_end = label_end_time_utc
setup_group_id
```

For each outer fold:

1. training is chronologically before test;
2. remove training rows whose event intervals overlap test;
3. apply embargo after test;
4. keep `setup_group_id` entirely in one side;
5. fit all learned transformations on training only;
6. use a disjoint chronological calibration tail;
7. choose threshold using calibration only;
8. evaluate once on outer test.

Structure:

```text
5 outer expanding walk-forward folds
3 inner expanding folds
```

# 26. Logistic configuration selection

For each inner-CV configuration:

1. generate inner OOF predictions;
2. calibrate on a disjoint chronological calibration segment;
3. apply pre-registered thresholds;
4. calculate Brier and trading utility.

Selection:

```text
A. Find the configuration with best mean Brier score.

B. Keep configurations within one standard error of best Brier.

C. Among those, choose highest mean expectancy per raw base signal
   at a threshold satisfying retention >= 40%.

D. Require positive expectancy in the inner OOF aggregate.

E. Tie-break:
   lower C
   then fewer effective features
```

This keeps calibration quality primary while aligning the final choice with trading utility.

# 30. Statistical power and MDE

Create:

```text
A3_ML_POWER_MDE_REPORT.md
```

## 30.1 Paired comparison unit

For every raw base signal:

```text
model_portfolio_R =
    model_take × y_net_R_p95_stress

rule_portfolio_R =
    rule_take × y_net_R_p95_stress

delta_R_raw_signal =
    model_portfolio_R - rule_portfolio_R
```

Skipped signals contribute zero.

This prevents a low-frequency model from appearing superior only because metrics are calculated on a tiny retained subset.

## 30.2 Block structure

Use:

```text
active trading day as base block
moving block bootstrap length = 5 active days
10,000 bootstrap replicates
```

## 30.3 Minimum detectable effect

Estimate the sample required for:

```text
+0.03R per retained trade
+0.05R per retained trade
+0.10R per retained trade
```

And for:

```text
positive delta_R per raw base signal
```

Use:

```text
two-sided alpha = 0.05
power = 0.80
empirical block variance
```

If current evidence is underpowered:

```text
status = CONTINUE_EVIDENCE
```

Do not force PASS or FAIL from an underpowered comparison.
